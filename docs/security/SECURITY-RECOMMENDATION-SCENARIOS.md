## Evidence and decision boundary

Each conditional recommendation retains its signal status, confidence and bounded relative evidence paths; each check retains catalog provenance, evidence needed, detection limits, next action and owner decision flag. Tests assert that detected fixture paths exist, all 15 IDs appear once in stable order, serializations repeat exactly, large evidence lists are capped, and hostile display text is escaped in serialized JSON. They also assert `checksExecutedByThisTool: 0`, no check result, no risk-acceptance decision, and no legal-compliance decision. `executionStatus: automated_now` describes separate existing automation, not an execution observed by this engine.

Source inspection cannot establish live identities or roles, CMS permissions, deployed headers, OAuth/provider dashboards, real customer data flows, live analytics collection, webhook delivery or replay behavior, PCI scope, privacy-law applicability, or offline business activity. A recommendation is **not execution**; a passing unit test is **not a security audit**; feature detection is **not legal compliance certification**. Human owners must confirm external facts and separately approve risk decisions. The approved three-advisory dependency exception remains governed by the existing dependency baseline and its expiry; these tests neither evaluate nor alter it.

## Reusable VitaNova Claude Code Skill knowledge

- Package or reference `scripts/security/inventory-project.mjs` (inventory schema version 1), `scripts/security/validate-check-catalog.mjs`, `scripts/security/recommend-security-checks.mjs` (report schema version 1), and `docs/security/SECURITY-CHECK-CATALOG.json` (catalog and inventory schema versions 1, 15 stable IDs). Include the focused scenarios and tests as behavior examples. Codex can use the same Node entry points and fixtures.
- Keep source fixtures separate from project evidence. For a new project, run its own bounded inventory and validate versions, all nine signal IDs, catalog references, and provenance before matching. Do not reuse La Segundita's detected features as defaults.
- Assert both positive matches and bounded non-matches. Package-only hints and incomplete source coverage require review; contradictory evidence must be visible or rejected. Preserve the distinction between source detection, check proposal, check execution, result, owner risk acceptance, and qualified legal determination.
- Emit deterministic, capped, escaped JSON with paths rather than source snippets or secrets. A later presenter must escape for its own output context. Keep live provider verification and any CI gate, active probe, remediation, or production decision behind separate authorization.
