# Security baseline CI

The single workflow in `.github/workflows/security-baseline.yml` runs on pull requests and manual `workflow_dispatch`. It uses a read-only GitHub token, checks out code without retained credentials, runs `npm ci` on Node 22, tests the audit comparator, collects `npm audit --json`, and compares each source advisory with `DEPENDENCY-AUDIT-BASELINE.json`. A separate job verifies that the PR base and head commits are present, computes their merge base, and runs TruffleHog OSS on the PR-only commit range. It fails if that range is empty or unavailable. Manual runs omit the PR range and scan history reachable from the selected ref; they are not a guaranteed scan of every repository ref. No scanner output is uploaded as an artifact. The scan uses GitHub Actions annotations without raw secret values and disables provider verification calls.

A third, review-only job runs the project security inventory and publishes a bounded job summary. Capability observations are informational; only a broken inventory generator or formatter fails that job. See `PROJECT-INVENTORY-AUTOMATION.md` for the schema, limits, and human-review boundary. The dependency and secret-scan decisions below are unchanged.

The baseline records exact advisory ID, source package, advisory severity, direct/transitive scope, immediate consumers reported by npm, installed lockfile node path, version, and dev/optional scope. Parent package warnings are not counted as new advisories. Any new ID, affected installed path/version/consumer/scope, or higher severity fails the audit job. Removed IDs are reported as resolved in the job summary. An invalid or unavailable audit report fails closed. The scanner job fails on detected secrets or scan errors. Secret scanning can miss exposed credentials, and an audit finding alone does not establish exploitability.

They remain known, unfixed advisories. The comparator checks approval and `reviewBy` against the current UTC calendar date, includes 2026-11-09, and blocks these findings starting 2026-11-10 UTC unless the owner records a new time-limited decision. New or changed findings fail even during the approval window. Review the baseline and any changes to this workflow or comparator as security-sensitive code. Do not refresh the baseline merely to make CI green.

When the audit job fails, read its summary. For a new or changed finding, inspect the advisory, dependency path, and reachable input before patching or requesting a separate risk decision. For an expired baseline, re-review the risks and update the documented decision. For a secret-scan failure, treat the candidate credential as exposed, revoke it if real, and remove it from the proposed commits. Do not paste secret values into issues or logs. Run the comparator locally with `node scripts/security/check-dependency-audit.mjs AUDIT_JSON docs/security/DEPENDENCY-AUDIT-BASELINE.json package-lock.json`; run its fixtures with `node --test scripts/security/check-dependency-audit.test.mjs`.

For the future VitaNova framework, detect advisory deltas by source ID and installed copy; require consumer compatibility checks before remediation; preserve the previous manifest for precise rollback; require recorded human approval for temporary acceptance or deployment; retain sanitized, dated evidence and re-review dates. These project-specific checks are a pilot, not a compliance certification.
